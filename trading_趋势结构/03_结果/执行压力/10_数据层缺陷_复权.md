# 数据层缺陷：`hfq_close = close × factor` 重复计算价格涨跌

- 发现时间：2026-10-28
- 发现者：交易容量与执行压力研究员
- 影响面：`01_数据/frozen/frozen.duckdb` 的 `daily.hfq_close`、`daily_qfq` 视图、`02_代码/数据层.py` 的 `daily(adjust="hfq"/"qfq")`
- 严重度：**高**（所有基于 `hfq_close` 的收益、指标、止损、MFE/MAE 都会失真）

---

## 1. 事实

冻结层的 `factor` 是**累计总收益指数**：

```
factor_t = Π_{s<=t} (1 + pct_chg_s/100)
```

它本身已经是“把官方除权调整后的涨跌幅逐日复利”的总收益价格序列。数据字典 §5.1 又定义：

```
hfq_px_t = raw_px_t × factor_t
```

这会把价格涨跌计算两次。

### 1.1 单只证券

`600030.SH`，2014-11-27 → 2014-11-28：

| 日期 | close | factor | hfq_close | pct_chg | hfq 收益 |
|---|---:|---:|---:|---:|---:|
| 2014-11-27 | 17.51 | 8.034897 | 140.6910 | +2.8790% | — |
| 2014-11-28 | 17.26 | 7.920175 | 136.7022 | −1.4278% | **−2.8351%** |

`hfq` 收益 = 2 × `pct_chg`。

### 1.2 全样本

主板 2008-01-01..2020-12-31，`|pct_chg|>0.1%` 的相邻行：

| 指标 | 值 |
|---|---:|
| 样本 | 7,097,435 |
| `hfq_ret / pct_chg` 均值 | **2.0006** |
| 中位数 | **2.0014** |
| `|hfq_ret − pct_chg| > 0.5pp` 行数 | **5,355,424**（75.5%） |

这不是个别除权日，而是全样本的系统性 2 倍。

## 2. 为什么会发生

- `factor` 的定义是总收益指数，日收益 = `pct_chg`。
- 再用 `close × factor` 构造“后复权价”，等于 `price × total_return_index`，日收益 ≈ `pct_chg + pct_chg`。
- 正确的总收益价格序列应当是 **`factor` 本身**（或 `raw × 只含除权事件的累计调整因子`，该因子只在除权日跳变，不由每日涨跌幅累乘）。

## 3. 对研究的影响

1. **收益率**：`hfq_close.pct_change()` 约为真实收益的 2 倍；任何用 `hfq_close` 计算的年化、波动、夏普、回撤都会被放大。
2. **指标**：`hfq_close` 的 MA/ATR/通道/分型/突破位都会被价格水平的双重复利扭曲；55 日突破、120 日均线等信号会系统性偏移。
3. **相对比较**：同一窗口内所有证券都按约 2 倍放大，排序可能仍近似，但阈值（如“突破 55 日高点”“ATR 过滤”）和绝对收益不可用。
4. **自检失效**：数据字典 §7 声称“复权收益 vs 官方 pct_chg 偏差 >0.5bp 的行 0”，与实测 535 万行偏差 >0.5pp 矛盾。`01_数据/_audit/自检结果.json` 的该项检查需要复核（可能比较的是 `bs_hfq_close` 或错误地对齐了日期）。

## 4. 本研究员如何处理

- 本目录（`03_结果/执行压力/`）的所有计算**不使用 `hfq_close`**。
- 信号、持仓估值、退出收益全部使用冻结层 `factor`（累计总收益指数）+ 原始价（成交/整股/涨跌停/费用）。
- 具体记账：
  - 持仓市值 = `shares × entry_close × factor_t / factor_entry`。
  - 开盘卖出 = `shares × entry_close × factor_{t-1}/factor_entry × (exit_open / preclose_t)`。
  - 收盘卖出 = `shares × entry_close × factor_t/factor_entry`。
- 该口径与 `02_代码/账户撮合.py` 的“原始价 + 公司行动”口径在 2014 年核对：费用与成交笔数接近，NAV 差 17.5%（见 `08_统一引擎复核.md`），差异主要来自统一引擎的“卖出后次日再投”保守滞后，而非复权。

## 5. 建议数据负责人做的事

1. 把 `daily.hfq_close` 改为 `factor`（或 `factor / factor_first`），不要乘 `close`。
2. 把 `daily_qfq` 视图改为 `factor / factor_last`，不要用 `close × factor / factor_last`。
3. 重跑 `01_自检_数据.py` 的“复权收益 vs pct_chg”检查；当前 PASS 是假阳性。
4. 审计所有使用 `hfq_close` / `DataLayer.daily(adjust="hfq")` 的第一阶段结果（结构族、趋势族、退出模块若用了冻结层 hfq，需要重跑）。
5. 在数据字典 §5.1 明确：`factor` 是总收益指数，`hfq_close` 不是“后复权价”；两者只能二选一，不能相乘。

## 6. 复现命令

```bash
cd /Users/admin/WorkSpace/trading/trading_趋势结构
python3 - <<'EOF'
import duckdb
con=duckdb.connect('01_数据/frozen/frozen.duckdb', read_only=True)
q="""
with d as (
 select symbol,date,pct_chg,hfq_close,
        lag(hfq_close) over(partition by symbol order by date) ph
 from daily where board='主板' and date between '2008-01-01' and '2020-12-31')
select count(*) n,
       avg(case when abs(pct_chg)>0.1 then (hfq_close/ph-1)*100/pct_chg end) ratio_mean,
       median(case when abs(pct_chg)>0.1 then (hfq_close/ph-1)*100/pct_chg end) ratio_med
from d where ph is not null and ph>0
"""
print(con.execute(q).fetchdf())
EOF
```

预期：`ratio_mean ≈ 2.0006`，`ratio_med ≈ 2.0014`。
