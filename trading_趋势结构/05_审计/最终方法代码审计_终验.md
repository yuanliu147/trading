### 3.2 新发现 N7（中）：EXIT "TB1/B0 −8.83%/−19.84%"的标签与配对错误

**报告写法**（4 处 + 机器可读 1 处）：

- `01:220`："`TB1/B0` 的 **−8.83%/−19.84% 是 full-window 基准/测试床臂**，单列，不计入 18 臂 dev best"；
- `01:349` §3.19 EXIT 行同；
- `00:75`、`README:59` 同；
- `04_最终结论.json families.EXIT.benchmark_full_window = {config:"TB1/B0", dev:-0.0883, val:-0.1984, type:"full-window benchmark"}`。

**我查到的事实**（四路交叉）：

| 来源 | TB1/B0 的值 |
|---|---|
| 总账 `c44f5ce6c367`（`EXIT@TB1/B0`，experiment，dev+val） | **dev −22.678% / val −22.427%** |
| `退出_臂对照_组合级.csv`（18 臂） | B0 dev **−22.678%**、val **−22.427%**（MDD −91.4%/−77.9%） |
| `退出_净值_TB1_B0_dev/val.csv` | 由 NAV 反算 dev −22.5%、val −22.4% |
| `退出_报告.md:226` | B0 **−22.7% / −22.4%** |
| **`退出_仓位敏感.csv`** | B0 / dev / **sizing=RB, risk_pct=0.005** → **cagr −0.088257**、mdd −0.683654、calmar −0.129096、n_trades 806 |

即：**−8.83% 是 B0 在"RB 仓位口径、单笔风险 0.5%"下的敏感性行**（总账 `ad904008b41f`，kind=sensitivity），既不是 full-window 基准，也不是 B0 基准；`退出_仓位敏感.csv` 只有 dev/val 两个窗口，项目内**不存在** B0 的 full-window 行。而 **−19.84% 是 18 臂 val best（S_struct，`12a1a0473291`）的 val**，不是 B0 的 val。

**正确写法应为**："EXIT 门槛表里 dev 最高 −8.83% 是 `TB1/B0` 的 **RB 仓位敏感性（风险 0.5%，只有 dev、无 val）**，不参与两窗口比较；两窗口可比的 18 臂 best 为 −20.20%/−19.84%；B0 基准 −22.68%/−22.43%"。

**影响**：EXIT 判定（拒绝）、18 臂 best（−20.20/−19.84）、32 个两段为正（该行 val 为 NaN，不计入）、全项目最高 dev/val 均**不受影响**。属"标签与配对错误"，不是数值结论错误。

**处置**：**不阻断负结果发布**；但该句在对外引用前必须按上面改写，`04 JSON` 的 `benchmark_full_window` 应改为 `b0_baseline{dev:-0.2268,val:-0.2243}` + `excluded_row{config:ad904008b41f, reason:"RB sizing sensitivity, dev-only"}`。代码侧对应 `02_代码/最终交付.py:639-646` 的硬编码常量。
