## 6. 负结果是否可信

**结论：可信；问题在交付口径，不在负结果本身。**

1. **60% 拒绝有硬证据**：1,250 个基线压力格 max 7.24%，192 个候选重定格 max 12.12%，0 格 ≥20%、0 格 ≥60%；最好两段 8.33%/8.71%，且 dev MDD −35.3%。60% 是 6.9 倍差距，不是“只差程序”。
2. **T0005 淘汰干净**：dev +4.16%/MDD −9.05%/103 回合，val −2.53%/MDD −13.80%/159 回合；val 五年逐年为负；bootstrap val 97.5% 上界 +0.43%；12% 风险门下 1.32%/4.65% 信号可用；平均持仓 0.83/1.62，93.1%/88.6% 现金。不是“引擎把正结果做成负”。
3. **负结果不是成本单一造成**：RELSTR 毛收益 dev 已 −13.4%/年；TRENDCALLBACK 去掉止损仍 −24.48%/−24.86%；多族事件层超额为负；成本约 0.36%/往返，不是异常惩罚。
4. **已知 bug 多为乐观方向**：v1 hfq 双计收益（已修）、`tp8` 丢左尾（已撤回）、`nopull` 前视（已禁引）、`out_date` 前视（0.0158%，让入场避开退市下跌）、TREND 创业板限价（让涨停买入/跌停卖出更容易成交）、VCB delist_window 缺失（方向保守）。没有发现把结果系统性压负的 bug。
5. **唯一干净的两段正配置 VCB-P20 也不过**：+6.50%/+5.37%，但事件层 dev −1.08%（t=−0.86）、val +0.92%（t=−0.49）；PBO 0.309/0.505；去前 5 后 val 0.7%/年；随机排序 +7.20/+6.16 高于强度排序 +5.67/+5.59。组合正收益不能从信号层复现。
6. **5 个 S3 正结果不干净**：TREND 使用更宽宇宙 + 创业板限价 bug；即使它们最终仍为正，也不满足事件层为正/去尾为正/未登记/统计显著等门槛。负结论不依赖它们。
7. **留出不跑是纪律，不是遗漏**：没有候选过 G1-G10，E1 未建立，5 年留出无法确认低个位数；不跑是合理的。但理由要改成“T0007 是事后补登记，不是预注册父试验”，不能继续写“no done val”。

**边界**：60% 的拒绝是“在该预注册的低杠杆、10 仓、1.2% 单笔风险、主板/宽基框架下”的拒绝；不能外推为“A 股不存在 60% 策略”。提高单笔风险、集中持仓、杠杆、日内等路径没有测试。
